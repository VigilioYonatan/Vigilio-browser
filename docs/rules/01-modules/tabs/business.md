# Caso principal — Pestañas
**Acción**: top/vertical, groups, pin, mute, duplicate, close, restore, tab menu.
**Precondiciones**: el usuario puede acceder al módulo y su perfil local está disponible. Para páginas remotas, verificar existencia/vigencia de pestaña, origen y permisos. Para operación del agente, require explicit client capability grant.
**Flujo**: (1) usuario invoca desde UI/command palette (2) controlador valida tipo/estado/permiso y límites (3) presenta preview/confirmación si afecta datos (4) adaptador ejecuta async sin bloquear UI (5) emite estado y persiste atómicamente cuando es necesario (6) UI anuncia resultado y ruta de recuperación.
**Invariantes**: sin nube/login, sin fuga interperfil, no mutación silenciosa, idempotency keys cuando el commit sea ambiguo. **Conflictos**: pestaña cerrada en paralelo se descarta de forma segura; cambio de perfil invalida comandos antiguos; doble activación se deduplica por id; datos obsoletos se revalidan justo antes de commit. **Errores**: entrada vacía/malformada, duplicados, permisos denegados, disco lleno, timeout antes/después de commit, reinicio inesperado, archivo grande, problema de renderer. **Recuperación**: cancelar tareas sin eliminar estado anterior; reintentar solo si acción idempotente; preservar backup y mostrar error accionable. **Audit**: guardar evento local sin payload sensible únicamente cuando fue una acción protegida. **Postcondición**: Navegación avanzada sin tabs duplicadas.
