# Workflow: shields-override
**Propósito**: Cambiar protección por sitio, re-cargar página, conservar estado per profile. **Actores**: usuario local, servicios de UI, dominio, SQLite/WebEngine/OS; agente únicamente si hay permiso. **Secuencia**: inicio desde UI → validación de permiso/origen → captura de operación estable/idempotency key → ejecución async → confirmación de persistencia/resultado → anuncio accesible → registro diagnóstico redactado. **Fallos parciales**: una pestaña o perfil desaparece a mitad de acción; proceso WebEngine crash; error SQLite; falta espacio o permisos; respuesta ambigua; timeout after commit. **Compensación**: undo cuando sea seguro; rollback del snapshot de datos; mostrar recuperación antes de cerrar. **Pruebas**: unit+integration+E2E serial con fixtures locales y requisitos de Senior Mode/teclado; seguridad y privacidad obligatorias. **Operación**: detectar y reportar sin payload sensible, no bloquea otras tabs salvo operación global. **Fuente**: módulos correspondientes en `01-modules/`.
