# Arquitectura y restricciones
CURRENT: apps/vigilio-browser/src/app.cpp, core/TabModel/UrlInput/SessionFile, ui/BrowserWindow, storage/LocalRepository, tests básicos, sin verificación de UI Qt en este paquete. TARGET: modular C++/Qt with UI/core/WebEngine engine/adapters/storage/security/privacy/performance/extensions/tools/readers/mcp/diagnostics. Módulos de dominio no dependen de Widgets ni de Chromium; UI consume interfaces C++ tipadas; WebEngine trata URLs y contenido remoto como entradas no confiables; handlers IPC/MCP pasan gateway de permisos. Capas: entrypoint → composition root → UI/controllers → domain/application contracts → SQLite/WebEngine/OS adapters. Errores tipados y señales Qt para async. SQLite fuera del UI thread cuando haya operaciones costosas; migraciones transactionales y backup atómico. Prohibido sandbox off y usar perfiles privados como persistentes. La página de inicio y visores de archivos no deben privilegiar una URL externa. Assets via Qt resources qrc, con exclusión de mockups.

**Qt constraints**: WebEngine es Chromium multiproceso; los gráficos / E2E dependen de la plataforma. No estimar RAM basándose solo en el proceso principal. Qt extension APIs MV3 version-sensitive; validar antes de documentar como funcional. MCP herramienta local stdio no implica modelo de IA; IAM y scope por cliente. Cache, HTTP2/3, TLS los controla Chromium, no reimplementar stack. **QStandardPaths** maneja almacenamiento; plataforma no comparte carpetas de perfiles a la fuerza. **Dependency policy**: terceros evaluados por licencia y actualización antes de incluir.
