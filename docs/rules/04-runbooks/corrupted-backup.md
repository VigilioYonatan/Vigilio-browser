# Runbook: corrupted-backup
**Trigger**: Backup no pasa checksum/schema. **Severidad**: evaluar según pérdida de datos/riesgo, no inventar prioridad. **Impacto**: operación interrumpida / posible estado parcial. **Safety constraints**: no borrar perfil, no transmitir dumps sensibles y no desactivar sandbox para diagnóstico. **Diagnóstico**: reproducir con fixture/snapshot, registrar app version/OS/Qt/test case, inspeccionar logs locales redactados y comparar hash de estado. **Contención**: aislar función afectada, mantener navegación core, revocar MCP si comprometido. **Remediación**: localizar owner del módulo, corregir con test de regresión y verificar reversibilidad. **Retry**: solo si se demuestra idempotencia; si commit ambiguo inspeccionar estado primero. **Verificación**: unit+integration+E2E relevante, test negativo, sin regresión de memoria/privacidad. **Rollback**: recuperar backup seguro y no eliminar el original. **Escalación**: maintainer del módulo / security reviewer. **Post-incidente**: raíz, timeline, nuevos tests y docs owners.
