# Prompt Builder y documentación

- Los micro-prompts deben ser pequeños, ordenados y dependientes del estado real del proyecto.
- **PROPOSE** diseña la solución completa del microcambio.
- **APPLY** implementa solo el alcance definido para ese microcambio.
- **REVIEW** compara resultado, pruebas y coherencia con la visión final.
- Cada micro-prompt debe revisar `/resultado/` cuando toque UI, assets, branding, instalador o accesibilidad.
- La documentación debe mantenerse sincronizada con el código y con los assets.
- No introducir carpetas o rutas fuera del acuerdo del proyecto sin documentarlo.
